Quick Start

Click Choose .pl files or drop PipeCAD project files on the box. You can add more at any time. Each file shows its project, units, PipeCAD version, floors and detectors.

2
Order them

Drag a row (or use ↑ and ↓) to set the order, and × to remove a file. The file marked header supplies the project-wide settings. Floors from the other files follow in list order.

3
Names

A floor whose name is already used by an earlier file gets a copy number (Area A (2)). Detectors and pipe runs keep their names. If a floor holds several detectors with the same name, you're asked to leave them or number them, one group at a time or with Leave all / Number all. To rename on purpose, set a naming convention (prefix and suffix, or find and replace) for the whole project or for each file. Every change is listed, and you can type a different name.

4
Review and download

The summary shows the merged floors and detectors. Read any yellow notes, set the file name in the side panel and click Download merged .pl. If it is disabled, the panel says why; click a message to jump to the item.

5
Design check and report

The tool reads the merged file back and compares every floor and detector with the originals. The PASS/FAIL strip shows the result. Print (or save it as PDF), Save .html or Save .csv to keep a record.

6
Verify in PipeCAD

Open the merged file in PipeCAD and verify that every floor, detector, pipe network and result matches the original drawings in performance and coverage. This is an experimental tool, and the user assumes all risks. The original files are never changed.

How the merge works

  • The design is copied unchanged. That includes every floor, detector, pipe run, sampling hole, end cap, T-piece, outline, label and saved PipeCAD result, with coordinates, hole sizes, fan speeds, alarm settings, flows and transport times.
  • Internal IDs. PipeCAD numbers each file's detectors, pipes and holes from 0, and the saved results point at those numbers. Each later file's numbers are moved up by one fixed amount, together with every results reference, so nothing collides and every result still belongs to the same pipe or hole. The project tree numbers move the same way.
  • File format. The merged file is written the way PipeCAD writes its own files: same XML header, indentation and Windows line endings. It is marked with the newest PipeCAD version among the inputs.

Naming rules

Names change only when they must, or when you ask. Everything else about a design stays exactly as it was.

  • Floors must be unique in the project. A floor whose name is already used by an earlier file gets the next copy number: Area A → Area A (2), then (3), and Area A (2) becomes Area A (3). Floors with the same name in one file are their designer's own and are flagged for your decision.
  • Detectors only need unique names on their own floor. Because merged floors are kept apart, detectors are never renamed automatically.
  • Repeated names. When one floor holds several detectors with the same name (for example four called Detector), the tool asks you to Leave as is or Number them. Numbering keeps the first and continues the pattern for the rest: Detector, Detector 2, Detector 3, or MASD 01 → MASD 02. Use All to choose for every group at once.
  • Pipe runs are locked unless you set a pipe naming convention. Exhaust runs always keep Exhaust first: a prefix goes after it, so Exhaust Pipe with prefix {detector} becomes Exhaust MASD 01 Pipe.
  • Naming conventions. Choose One convention for the whole project or A convention for each file. For floors, detectors and pipe runs, pick Prefix / suffix (text added before and after each name) or Find & replace (every occurrence of some text replaced, case-sensitive). Prefix, suffix and replacement can use {file} (the file name without .pl), {floor} and {detector}. Match pipe names to detector sets the pipe prefix to {detector} . A convention is applied first; a floor that then clashes with an earlier file still gets a copy number.
  • Typing a name. Every changed floor and detector is listed with the reason, and you can type a different name. A floor name must not match another floor; a detector name must not match another detector on the same floor.
  • Length limits. PipeCAD allows at most 32 characters, spaces included, for floor, detector and pipe-run names, and new names are held to that. When a copy number or numbering would pass the limit, the name is cut and ends in ...(n), n being the copy number: Boyers Roadway 2 x Pipes/MASD → Boyers Roadway 2 x Pipes/M...(2). A prefix, suffix, replacement or typed name that is too long is refused with a message instead. Original names are never shortened.

Design check and difference report

After every merge the tool reads the merged file back and compares it with the original files, so you can see that each design came through unchanged. The result appears under 5 · Design check.

  • Fingerprints. Each floor and detector gets a SHA-256 fingerprint of its whole design: pipe runs, pipes, coordinates, sampling holes, end caps, T-pieces, detector settings, outlines, labels and the saved PipeCAD results that belong to it. Only what a merge is allowed to change is left out: floor, detector and pipe-run names, and PipeCAD's internal ID and project-tree numbers. If the original and merged fingerprints match, the design is identical.
  • ID numbers. The check confirms that each file's internal IDs moved by one constant amount (the ID shift), so every saved result still points at the same pipe or hole.
  • Nothing extra or missing. Every floor and detector must be found, the merged file must not hold anything that isn't in a source file, and its project settings must come from one of the files.
  • Results. ✓ Identical means the design matches at its expected place; Identical (moved) means it matches but sits somewhere else in the file; ✗ Changed lists the first values that differ; ✗ Missing means it was not found.
  • The report lists every file with its SHA-256 checksum and ID shift, then every floor and detector with its original and merged name (marked automatic or typed by you), contents, fingerprints and result. Use Show report to read it, Print report to print it or save it as PDF, or Save report (.html) to keep a copy that opens in any browser.
  • Check an existing merged file. Keep the original files in step 1, then use Choose merged .pl at the bottom of the page. The order of the originals doesn't matter.

The check reads the file's contents. It doesn't replace opening the merged file in PipeCAD and verifying the designs there.

Project settings and which file goes first

A PipeCAD project has one set of project-wide settings. The merged file takes them from the first file in the list:

  • Project details: name, location, designer, company, address and contact.
  • Units, snap grid and view.
  • Pipe type: name, bore, outside diameter, stick length and part number.
  • Default options for new detectors. Existing detectors keep their own limits, hole sizes and sensitivity.

Put the file whose project details and pipe type you want to keep at the top.

FAQs

Will the design or the calculated performance change?
No. Every value in every floor, detector, pipe, hole and saved result is copied exactly. Only internal ID numbers and the names listed in step 3 change. The Design check after each merge confirms this design by design, and the difference report can be printed or saved. tools/verify_merge.py in the repository runs a similar check outside the app.
Can I merge two revisions of the same project?
Yes. The later file's floors get copy numbers, such as Area A (2), so you can compare the revisions side by side in PipeCAD. To mark them more clearly, give the later file a floor suffix such as Rev B under A convention for each file.
Can I merge a merged file again?
Yes. A merged file is an ordinary PipeCAD project, so you can add it to another merge.
Which PipeCAD versions work?
Files from PipeCAD 3.5.0.132 and 3.6.2.139 have been merged and opened in PipeCAD. Other 3.x files are likely to work. Open the result in PipeCAD to confirm.
Does it change my original files?
No. It only reads them and downloads a new file.
Can I use the merged file in the MASD Field Report?
Yes. Use Import PipeCAD (.pl) there. Each detector becomes one sheet. Detectors on different floors can share a name, so to tell the sheets apart, add a detector prefix such as {floor} or a per-file prefix before merging.
Does the design check prove the file works in PipeCAD?
It proves the file's design data is identical to the originals, apart from names and internal numbers. It can't run PipeCAD, so still open the merged file in PipeCAD and check it there.
Can I check a merged file later?
Yes. Add the original files in step 1, then use Choose merged .pl under Check an existing merged file. The originals can be in any order.

Install and privacy

This tool runs entirely in your browser. Files are read on this device and never uploaded. After the first visit it works offline. To install it as an app, use your browser's Install option (Chrome or Edge: the install icon in the address bar; Safari on iPhone or iPad: Share → Add to Home Screen). A Windows installer is also available: download PipeCAD-Project-Merge-Setup .exe from the latest release. It isn't code-signed yet, so Windows may show a SmartScreen warning: choose More info, then Run anyway.
